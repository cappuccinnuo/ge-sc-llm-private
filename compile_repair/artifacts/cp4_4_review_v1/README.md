## 结论

1. **成立的部分**
   - CP4.3 审查的两个探针在新评分器下：中性插入 7/7，插入并改一个常量 6/7（CP4.3 为 3/7），原位恢复加改动 6/7（identical）；Yul 插入 16/16、汇编块内加注释 16/16、改错 case 常量 14/16（partial，exact false）。
   - 移动自检：对比 `cp4_3_v1/moves.jsonl.gz` 与 `cp4_4_v1/moves.jsonl.gz`，200 项中只有 cp3_00291 改变（kept 261 → 262/267，调用匹配 132 → 133），与报告一致；surviving 三个比例为 1 的仍为 199 项。
   - 测试：审查环境运行 `test_cp44.py` 到 `test_benchmark.py` 共 279 项通过、5 项跳过。
2. **未解决的问题：被移出推导的节点按原样比较，可能把错误节点计为相等**（`probe_stale_name.json`）。
   - 编号平移时，原样比较本身不可信：真值中的 `TMP_4` 在修复图中应为 `TMP_8`，如果修复图中某个使用节点仍写 `TMP_4`，它字面上与真值相同，实际上读的是另一个值。
   - 实测：一个旧名使用节点时，评分 2/3，数量碰巧正确，但计为相等的是错误的使用节点，正确的定义节点被计为不相等。三个旧名使用节点时，只有 2 个节点真正正确，评分为 4/5，高估。
   - 原因：冲突时把双方节点都移出推导，再按原样比较。高估在 CP4.2 引入的原分回退中就已存在（CP4.3 的整体放弃同样给出原分 3/5），CP4.4 没有引入也没有消除它。
   - 后果：评分在少数情况下会把错误修复算作更好，这与 CP4 起“故意错误不得计为相等”的要求冲突。
3. **另一处不一致**：参与推导要求除 IR 外的全部事实相同（含 length），而主指标只比较节点类型与 IR。汇编块内加注释时 ENTRYPOINT、ASSEMBLY、ENDASSEMBLY 三个节点因 length 改变被移出，再按原样比较（Codex 报告中写明）。在新规则下应与主指标使用相同的事实。

## 处理

CP4.5（PROMPTS §4.6f）：名称对应改为以定义为锚：每个生成名称的映射由它在真值中唯一的定义处决定；使用处必须与定义处的映射一致；没有锚的名称只在不与任何已锚名称冲突时按原名接受；不一致的节点计为不相等，不再按原样比较。
