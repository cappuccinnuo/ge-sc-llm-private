# CompileRepair 文档目录与记录规则

本目录保存 CompileRepair 模块的交接文档、运行与改动记录、决策记录。格式沿用 NodeSem 在仓库根目录 `HANDOVER.md` 与 `docs/training_changes_2026-10-07.md` 中的写法（交接段落 + 编号的五段式详细记录）。区别：本模块的记录只写在本目录，不再追加到仓库根目录的两份文件（理由见“与仓库根目录记录的关系”）。

## 文件与用途

| 文件 | 用途 | 写法 | 谁写 |
|---|---|---|---|
| `HANDOVER.md` | 交接文档：新接手的人（或新的 Codex/Claude 会话）先读它。上半部分是当前状态与必读事项，下半部分是按时间追加的交接记录 | 上半部分在状态变化时更新；交接记录只追加 | 每次任务结束 |
| `CHANGE_LOG.md` | 运行与改动记录：每次任务的详细记录（对应仓库根目录的 `docs/training_changes_2026-10-07.md`）。本模块的“运行”指编译、Slither、LLM 调用与评估，没有 HGT 训练 | 编号小节，只追加 | 每次任务结束 |
| `DECISIONS.md` | 决策记录：D1–D13 及以后的决策，每次状态变化追加一行历史 | 当前表可更新；历史表只追加 | 决策变化时 |
| `../PROGRESS.md` | 简要进度：每个 Prompt 一节，列出做了什么、文件、测试、验收数字 | 只追加 | 每个 Prompt 结束 |
| `../CPn_REPORT.md` | 单个 Prompt 的完整报告，格式见 `../REPORT_TEMPLATE.md` | 新文件 | 每个 Prompt 结束 |
| `../PROMPTS.md` | 方案与 Prompt 原文，按修订号（r1、r2…）整体修订 | 由 Claude 修订 | 方案变化时 |
| `AGENT_INTERFACE.md` | LLM 代理的接口说明：对模型 API 的要求、配置文件字段、运行与费用控制、运行后留下的记录 | 接口变化时更新 | 修改 agents/ 时 |

## 强制规则：每完成一个编码任务都必须记录

“编码任务”包括：执行任何一个 CPn Prompt（含其中途停下）、Prompt 之外的修复或补测、方案修订、产生新产物的运行。只读讨论不算。

每个编码任务结束时，在提交之前必须完成以下全部内容，缺一项不得提交：

1. `CHANGE_LOG.md` 追加一个编号小节，按下方“详细记录模板”五段写全。
2. `HANDOVER.md` 交接记录部分追加一段，按下方“交接记录模板”；若当前状态、下一步、必读事项发生变化，同时更新上半部分对应条目，并在交接记录中写明改了哪几条。
3. `PROGRESS.md` 追加一节；执行 CPn 时另写 `CPn_REPORT.md`。
4. 决策状态有变化时，更新 `DECISIONS.md` 当前表并在历史表追加一行。
5. 对所有新建或追加的文档运行 `python -B -m scripts.node_sem.doc_check --expect-cjk <文件>:<追加前字节数> ...`（新文件不带字节数），全部通过；结果写进 CHANGE_LOG 第 5 段。

记录要求：
- 只追加，不改写旧记录。发现旧记录有错时，追加“更正”小节，写明原文位置、错误内容、正确内容与依据。
- 每个数字给出来源（命令、产物路径、SHA256、计数文件）。没有运行的事项写“未运行”，不写“通过”。
- 写明修改者（修改 AI：Codex / Claude；用户亲自修改写“用户”）。
- 时间使用 America/New_York（11 月起为 EST，UTC−05:00）。需要精确时间时写出依据（命令输出、文件 mtime 或提交时间）。
- 区分“已经修改”与“建议、尚未实施”。
- 用户的批准、拒绝与方案外的调整，写明原话要点、日期与影响范围。
- 不写入 LLM 密钥、个人信息或外部语料的源码全文；外部语料只写路径、提交号、SHA256 与计数。

## 交接记录模板（HANDOVER.md）

```text
### YYYY-MM-DD CompileRepair <任务名，例如 CP0> 完成（修改 AI：Codex）

<第 1 段：分支、起始 HEAD、读过的文档（PROMPTS 修订号）；新增/修改了哪些文件；明确哪些原有内容未修改。>

<第 2 段：主要结果与数字（带来源）；验收是否通过。>

<第 3 段：与 PROMPTS.md 不一致之处、用户批准、待确认问题；停在哪里，下一步的前提。>

<第 4 段：测试与检查命令的结果；是否本地提交、是否 push；没有做的事（训练、下载、安装、LLM 调用等）。>
```

段落要求写成完整句子，NodeSem 交接记录的密度为参照：一段 3–6 句，每句都有具体对象或数字。

## 详细记录模板（CHANGE_LOG.md）

```text
## N. YYYY-MM-DD CompileRepair <任务名>：<一句话标题>（修改 AI：Codex）

### N.1 任务、依据与范围
用户要求、读过的 PROMPTS 修订号与章节；起始分支与 HEAD（pull 结果）；本轮范围与不在范围内的事项；新增与修改的文件完整清单；明确未修改的冻结内容。

### N.2 实施方式和重要选择
逐模块说明实现方式；每个非显然的选择写明备选方案与取舍理由；复用了哪些已有函数（路径与 SHA256）；复制冻结函数时的等价测试；遇到的问题和处理（包括被拒绝的操作及改用的方法）。

### N.3 实测与数据结论
所有运行的输入身份（语料、版本、SHA256）、数量、结果、耗时与资源；表格优先；结论只写数据能支持的部分，不能支持的写成“未证明”。

### N.4 用户批准、原文差异与待确认设计
用户批准与拒绝（日期、要点、影响）；与 PROMPTS.md 的差异及处理；只登记、未实施的建议（编号列出）。

### N.5 验收、资源、未执行事项与停止
逐条验收项：预期、实际、是否通过；测试命令与通过/失败/跳过数；doc_check 结果；未执行事项；提交号与是否 push；停在哪里。
```

## 与仓库根目录记录的关系

NodeSem 与 EdgeSem 把记录追加到仓库根目录的 `HANDOVER.md` 与 `docs/training_changes_2026-10-07.md`。`compile-repair` 分支与 `edge-sem` 分支并行开发，两边都向这两份文件末尾追加会在合并时产生冲突，所以本模块的记录只写在本目录，并禁止修改根目录这两份文件。将来合并到集成分支时（PROMPTS.md 第 5 节），在根目录 `HANDOVER.md` 追加一段指向本目录的说明即可。
