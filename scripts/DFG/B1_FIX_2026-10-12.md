## A. 原因及原位置

修改前 semantic_cfg.py 的 L14–17 只扫描 view.functions 中的同名函数，忽略状态函数类型变量；L113–118 根据 callee 的名称判断 selfdestruct/revert/suicide 必然终止。revert_statement 还被直接当成终止。

B1 最小样例（本轮未编译，不把 tree-sitter 接受视为编译通过）：

~~~solidity
pragma solidity ^0.5.17;
contract C {
    function(address payable) internal selfdestruct;
    function g(address payable a) internal {}
    constructor() public { selfdestruct = g; }
    function f(address payable a) public returns (uint) {
        selfdestruct(a);
        uint x = 1;
        return x;
    }
}
~~~

旧分析把 selfdestruct(a) 当作内建，漏掉 uint x=1 → return x，且将 f 计为 supported、无回退。更换变量名称为 handler 时该事实存在。绑定必须先于终止判定。

修改前完整源码快照位于 [audit/b1_fix_2026-10-12](audit/b1_fix_2026-10-12/)；没有用 git restore 覆盖用户既有修改。

### 绑定分类的具体边界

1. 裸标识符：先查询现有 SymbolTable 的局部作用域及可见时点，再检查当前合约和 source unit 的声明。声明扫描覆盖整个对应作用域，不只看调用之前的文本；其他合约内部或其他函数参数不会污染当前作用域。
2. 唯一可见用户函数：确认非内建，沿用原普通调用的实参读取和可能正常返回路径。没有推断该函数实际是否返回，也没有做跨函数摘要。
3. 唯一同名状态函数指针：只确认它不是全局内建，并记录声明位置；不解析指针目标、不跟踪其状态内容。沿用原普通调用规则，修复的是错误截断，不是增加状态分析。
4. 成员调用 obj.selfdestruct(...)：语法上不是裸全局内建，分类 non_builtin；不声称解析了 obj 的完整类型/目标。
5. 导入、继承、重载/重复候选、不可调用声明、无法解释的计算型 callee：unknown，函数级回退。没有用“没找到声明”直接证明内建。
6. 本 grammar 的 revert(...) 会成为 revert_statement，仍需按绑定判断。revert Error(...) 是另一种形式，记录 custom_error_revert；当前不能完成自定义错误绑定，明确回退，不将其与裸调用混为一类。
7. 嵌套的内建终止调用不能由当前语句 CFG 准确表达，明确回退，不能假装普通表达式继续。
8. 对已确认内建，仍先提取实参 USE，再截断后继。函数类型参数/局部变量仍受原标量 SymbolTable 限制并回退，没有增加其数据流分析。
9. 本分类器只覆盖 B1 涉及的潜在终止名称；其他调用沿用原 MVP 规则。这不是全 Solidity 名称解析器。

### 版本策略

复用原版本区间解析器，记录 lower_inclusive / upper_exclusive，不记录虚构的 selected compiler version。只有整个允许区间都落在本模块审计的可用范围，且可见声明/导入/继承检查通过，才确认内建。

- selfdestruct：当前审计的 Solidity 0.4.x–0.8.x 范围。
- revert：下界至少 0.4.10；较早版本或跨其引入边界的范围回退。
- suicide：仅整个区间低于 0.5.0 时确认旧内建；0.5+ 未声明的 suicide 回退，不能假设仍是终止别名。存在 experimental pragma 时更保守地回退。
- 缺少 pragma，仅指定 scope_mode，不等于指定编译器版本；不能据此确认内建可用。
- 无上界且超出已审计语言范围、跨 scope 边界、不支持的 pragma 形式不猜版本。原前端可能先执行文件级版本回退；本轮没有扩大其接受范围。
- 同名用户声明已确认时，不因旧内建被移除而把该用户声明当成内建。

一手依据（只读资料，没有下载可执行程序）：
- [Solidity 0.5.0 breaking changes](https://docs.soliditylang.org/en/v0.5.17/050-breaking-changes.html#functions)：suicide 被移除。
- [Solidity v0.5.17 Changelog](https://github.com/ethereum/solidity/blob/v0.5.17/Changelog.md)：0.4.10 引入 revert；selfdestruct 的历史别名信息。
- [Solidity 0.5.17 function types](https://docs.soliditylang.org/en/v0.5.17/types.html#function-types)：函数类型变量的语言机制；资料说明不是本地样例的编译证书。

## D. CFG、DDG 与投影验证

- 内建 selfdestruct / 旧版 suicide / revert：后继被截断，实参的定义→使用依赖仍存在。
- 唯一同名用户函数、状态函数指针、成员调用：正常后继和依赖保留。
- 函数/状态声明在调用之后仍可识别；现代局部声明按可见时点、旧作用域按原 legacy 策略解析；关闭的内层块、其他函数和其他合约的同名声明不一概混淆。
- 真实 HCG 测试逐字节检查旧节点属性，包括 token ndarray、漏洞标签、源码行；保留原 node_id/顺序和原边 key/重数，包含平行边。增强只增加 DATA_DEF_USE。
- use_ddg=false 与原图 fingerprint 一致。未改模型的 CFG/CG，不以分析 CFG 替换原图。
- 无法投影的写入在 RD 中仍执行 KILL：删除测试图中的 x=2 节点后，不会恢复被覆盖的 uint x=p → return x 假边。
- 缺失 if 的测试图仍按独立语义 CFG 做双分支 union，不把两个赋值当成一条顺序路径。
- 投影继续按精确 AST/代码/端点匹配，不按最近行猜测。语义不支持的 assembly 测试不提交此前已分析的部分 DDG。
- 以上缺失节点是测试构造的不完整冻结图，不是对数据集进行删节点操作。生产 projection.py、RD、DDGBuilder 和 pipeline.py 均未修改。

## E. 函数级回退与隔离

绑定 preflight 在创建语义 CFG 块之前完成。未知调用抛 BindingUncertain，analyze 只记录 function_fallback，不追加该函数 IR；DDGBuilder 没有机会对其运行 RD/提交 facts。其他函数独立继续。

专门验证了：回退函数的调用前已有两条赋值，仍然没有任何该函数的残留 facts 或投影边；同文件 good 函数的 uint z=v → return z 正常保留。

诊断包含 function、function_start/end、file、call_name、call_form、start/end、line/column、classification、reason、evidence。依据可包含同名声明坐标、导入语句、继承列表或 pragma 区间。位置属于原源码，字节偏移为 UTF-8，行号从 1 开始；column 为 tree-sitter 的字节列加 1。

“函数级回退”指此函数不贡献新增 DDG，原 HCG 的函数/合约/标签仍保留，不是删除样本。其他原有文件级语法/版本/投影回退仍遵循既有策略。
