# NS-P8b N-C2：学生蒸馏与完整对照结果

2026-11-09，执行、汇总与修改：Codex。原名视图，本机RTX3050、单seed，冻结G3R图与L-audit协议。

**60/60次正式拟合及验收完成：S5 30次、S8 30次，失败0、重试0。结论：没有证据证明学生增强在主任务上稳定改善；访问控制节点存在误报减少的局部收益，合约级best未改善。**

主终点是重入节点G3R、best外层Buggy-F1。S5−S4折均差+0.008145个百分点，满足严格大于0的资源执行条件，因此完整执行S8；这只是继续对照的规则，不是效果成立的门槛。S5−S4原始/校正p=0.645603，S5−S8原始p=0.136838、Holm后0.273677。

## 1. 配置与评估口径

- S4 = CODE 256维 + CTX 256维 + STATIC 245维及各模态存在位；S5在其上增加384维STUDENT及存在位。拼接载体760→1145维，再经原适配/HGT计算。
- S6为历史N-C1教师向量配置；S8为本次学生向量按同任务、同折、同节点类型固定置换的对照。S5/S8全部零步参数和训练随机起点一致。
- G3R仍为作者CG/CFG融合HCG加已经封存的DFG增量。图、标签、原折、模型核心、训练配置、TF32和best规则未变。学生、教师阶段未在本轮重跑。
- best按最低inner_val loss选择，outer_test只作训练后评分；这是分组交叉验证的外层评估，不是外部独立测试。节点按HCG节点计数，不是去重源码行。L-audit仍是诊断标签视图，不是已证明的金标准。
- S4旧best/last共60份已按历史授权删除；本轮只读核对原收据和预测，不声称当前重载S4。S6的60份及本轮120份checkpoint文件均按收据核验。

## 7. 验收、交付与研究结论

60份新收据及120个best/last文件SHA核验通过；历史S6 30份收据及60个文件核验通过；S4 30份预测/收据只读引用。主标签与原标签分开重算，按任务、折、文件、源码SHA、HCG节点身份对齐；全部OOF身份无重复。训练设备与TF32一致。21项新增报告测试通过；完整回归NodeSem1341、DFG v2 2653、legacy223，共4217项通过，42条既有警告。冻结8H354份、N-C1 375份、N-C2 388份源码保持不变。

本轮有局部收益，但不足以确立可普遍推广的学生增强：主任务差异很小且未获统计支持；访问控制节点主要减少误报，真实正例召回仍低；合约best无提升。保留S4为既有基线，完整保存S5/S6/S8作为研究对照。后续应优先围绕真实样本召回和跨数据来源验证研究；本轮不自动增加seed、模型、漏洞类别或继续NS-P9。最终服务器实验将在显存充足设备另建批次，本机4GiB仅开发限制，两批不混合或择优。

机器可复核文件均位于artifacts/batch_NC2_v1/reports/：report.json、fold_metrics.json、fold_counts.csv、paired_folds.csv、best/last_fold_means.csv、orig_all_fold_means.csv、pooled_oof.csv、prediction_changes.jsonl、nonSolidiFI_positive_pairs.csv、file_error_changes.csv、resources.csv、teacher_gap.csv、relation_support_gradients.json、integrity.json及收据。只读汇总命令：mando CPU python -B -m scripts.node_sem.nc2_reporting；已存在reports时拒绝覆盖。
